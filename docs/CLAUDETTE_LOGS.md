# Claudette logs — the contracts

Every file under claudette's `logs/`: what it holds, its schema contract, and its single writer.
Read this when adding a log, consuming one, or tracing where a number in the status line comes
from. Script comments cite these entries by name — treat frozen keys as frozen.

Scope note: historical cost/usage *reporting* is deliberately out of claudette's scope — that is
a job for transcript-reading tools (they read the JSONLs that exist anyway). Claudette acts on
live limits; do not add reporting features here, point the user to such a tool instead.

## Logs
`logs/` inside the claudette folder (gitignored; created on demand by the hooks — do NOT track
its contents). Names follow **`<family>_<member>`**, where the member says what the data IS, not
the mechanism that produces or consumes it:
- `logs/claude_usage_last.json` — last MEASURED usage snapshot, atomically overwritten by `hook_statusline.py` on every render **that measured at least one window**. Single writer (the status line), so no collision. Read this for latest usage. **Absence is unknown, never 0** (added 2026-09-17): a session's first renders arrive before its first API response and carry no `rate_limits` at all, so such a render is logged to `claude_usage_snapshots/` (what that render SAW) but does **not** overwrite this file (what anyone last MEASURED) — otherwise the account-wide numbers every other session reads were replaced by an empty block stamped with a current `ts`, i.e. a *fresh zero* no staleness check can catch. Two rules follow for readers: never `get(..., 0)` a missing percentage — a window the snapshot does not carry is not evaluated (`hook_throttle.py`) or renders a yellow `?` (`hook_statusline.py`); and `ts` is the measurement time, which is what makes `STALE_S` and the background-job `used + 10*age_h` extrapolation mean anything. Exception: the very first render on a machine writes the file whatever it measured, so the file always exists. **Partial payloads do occur and are NOT covered by that guard** (measured over one fixed 20-hour range, 2026-09-17 16:00 → 2026-09-18 12:00, 280 renders: 270 carried both windows, 9 carried `seven_day` alone, 1 carried neither; the reverse shape — `five_hour` alone — did not appear. A "last N renders" window is not a checkable claim here: several sessions write this folder continuously, so it slides while you read it). A partial satisfies the guard, so it is written raw and the window it omits loses its last measured value until the next full render (observed gap: ~11s). Consequences are the fail-open ones: `hook_throttle.py` does not evaluate a window it cannot see, and the status line renders `?` for it. Four of those 9 landed within 8 seconds after the `five_hour.resets_at` that the surrounding renders carried, in four different sessions at once — i.e. that shape is machine-wide at the reset instant, not per session; the other 5 were not near it, and no cause is claimed here. **Whether the guard should be per-window** (only overwrite a window this render measured) is open: it would keep each window's last measurement, at the cost of one `rate_limits` block holding two measurement times — the provenance mixing rejected in `CLAUDETTE_DESIGN.md` (design notes, not published) for the empty case. A setup whose payloads never carry `rate_limits` at all would keep a first-render file that never advances — `--doctor`'s `statusline` row reads that `ts` as "last render" and would age; not worked around, since nothing to throttle against is the correct reading of that setup. **Additive-only schema contract**: frozen keys `ts`, `iso`, `ctx_pct`, `rate_limits` (never rename/remove/restructure); `ctx_pct` is what Claude Code sent: `0` together with `ctx_tokens.total` 0 means no reading (after a compaction, which Claude Code also runs on its own in an idle session), and it is `null` when the payload carried none (before a session's first call; from 2026-10-14, when the hook stopped crashing on that shape) — the same reader rule as `rate_limits`, never a measured 0; added sibling keys `ctx_tokens` (input/output/cache_creation/cache_read/total), `ctx_window`, `cost_usd`; added 2026-07-16 (throttle): `session_id`, `model`, `caps` (five_hour/seven_day curve caps + h_remaining/d_remaining); added 2026-07-21 (status keyword): `line` (rendered status line, ANSI-stripped); added 2026-07-27 (scoped limits): `scoped_limits` (list of {name,pct,resets_at,severity,active}, e.g. Fable weekly; null if unavailable/stale — from `claude_limits_last.json`); added 2026-10-16: `account` (email of the account these limits belong to; the status line borrows a reading from this file only for the same account).
- `logs/claude_usage_snapshots/status_<ms>_<pid>.json` — one file per status-line render **that saw something new for its session** (since 2026-10-01: its `cost_usd` moved, its `rate_limits` changed, or there is no previous render to compare with in `logs/sessions/<id>.json`, which carries `rate_limits` for that purpose). A repaint that repeats the session's last values is not logged: it would be an old reading under a new `ts` (`CLAUDETTE_DESIGN.md` "A snapshot is a reading"). Otherwise logs everything **for now** to observe behavior. **TODO (future): decide keep / drop / summarize** — this folder grows unboundedly; add a purge or a periodic conciliation to a `status_history.jsonl` once we know what's worth retaining. **It now has a real consumer**: `profile_skill.py` brackets skill runs against it, so a purge must SUMMARIZE, not delete — keep at minimum `ts`, `rate_limits.five_hour.{used_percentage,resets_at}`, `session_id`, `model`, `cost_usd` per render.
- `logs/sessions/<id>.json` — this session's last render: `{ts, iso, session_id, model, ctx_pct, cost_usd, line_session, rate_limits, rate_limits_seen}`. Single writer: `hook_statusline.py`, every render, atomic replace; files untouched for 7 days are pruned. `rate_limits` is the payload's, as received — what the next render compares with to decide whether to log a snapshot. `rate_limits_seen` (added 2026-10-16) keeps each window as last received when the payload drops it, so the status line still knows a window's reset passed after the redraw that dropped it (`CLAUDETTE_DESIGN.md` "At a window's reset"). Read by `dot_sess.py` and `hook_compact_done.py`, among others.
- `logs/claude_limits_last.json` — cloud limits snapshot (added 2026-07-27) from the UNDOCUMENTED `api.anthropic.com/api/oauth/usage` endpoint; the only source of model-scoped weekly limits (e.g. Fable). Single writer: `claude_limits.py refresh` (detached subprocess; never blocks a render). **Frozen keys** (additive-only, like `claude_usage_last.json`): `ts` (last success), `iso`, `ok`, `scoped[].{name,pct,resets_at}`; plus `attempt_ts`, `error` (stale-if-error keeps old data), `session_pct`, `weekly_pct`, `severity_max`, `spend_percent`, `extra_usage`, `raw` (full response). TTL 5 min, 60s when any bucket ≥80% / severity ≠ normal / last attempt failed. Creds READ-ONLY (`.credentials.json`; macOS Keychain fallback gated on `keychain_ok.json`, 3s timeout); never writes the refreshToken. Kill switches: `logs/claude_limits_off` (whole feature), `logs/scoped_hint_off` (the `(auth?)` hint only). Renders `w:8%(F:15%)/5d` — consumed pool colored, idle pool gray; `(auth?)` when the cache reports `ok:false`; dropped if cache >1h stale. Rationale (endpoint choice, render placement, colors, TTL curve, hint-over-silence): `CLAUDETTE_DESIGN.md`.
- `logs/claude_limits_request.json` — the latest refresh request `{ts, pid}` (30s min between spawns). Single writer class: `get_limits()` callers (statusline renders), atomic overwrite.
- `logs/keychain_ok.json` — macOS-only marker (added 2026-07-27): Keychain access verified by the `features_apply.py` probe; `claude_limits.py` refuses Keychain reads without it. Single writer: `features_apply.py` (creates on probe success, deletes on re-probe failure; re-probes silently with a 5s timeout and warns if access was lost). Not needed when `.credentials.json` exists. **Authorize / re-authorize: `features_apply.py --auth`** (probe only, touches no config file); the probe prompt defaults to yes with no interactive terminal. Rationale (popup gating, no-TTY default): `CLAUDETTE_DESIGN.md`.
- `logs/watchdog_off` — global auto-done kill switch; `logs/watchdog/<session_id>.off` — per-session one (added 2026-08-06). Single writer: `watchdog_switch.py` (whichever door calls it — the `.autodone on|off [all]` dot-command or the CLI); `hook_watchdog.py` only reads. Presence = disabled; content is only a timestamp. **No arming ledger exists on purpose**: whether a session is armed is derived from its transcript (a `CronCreate` tool_use carrying the watchdog marker = armed, a user message carrying the marker = it already fired), which keeps the single-writer rule intact and cannot drift from reality.
- `logs/update_hold.json` — an install's update that the screen held: `{from, to, findings[]}`, each finding `{kind, file, detail}`. Single writer: `update_screen.py` (`pull` writes it on a hold and deletes it on a clean update or none; `advance` deletes it after the fast-forward to `to`). Read by `features_apply.py --update-plan` (`update_held`) only while `from` is still `HEAD`, so a reinstall or a manual update leaves a stale file that nothing reads.
- `logs/idle_timer/` — `auto_done`'s idle timer state, per session (added 2026-10-17): `<session_id>.json` `{token, armed_at}` (the newest sleeper's token; an older sleeper that reads another one leaves), `<session_id>.ended` `{ts, reason}` (written at SessionEnd; a sleeper armed before it leaves), `carry.<claude_pid>` `{ts, from}` (a `/clear` hand-off of `.autodone off`, consumed by the next SessionStart of the same process within 60 s). Single writer: `hook_idle_timer.py`; files untouched for 7 days are pruned on each arm.
- `logs/idle_timer_decisions.jsonl` — what each idle timer did, one JSON line per event: `{ts, iso, session_id, event: arm|superseded|ended|wait|wake|stand_down|skip|switch carried, reason, token, idle_min, phase, ctx, cache_left}` (added 2026-10-17). Single writer: `hook_idle_timer.py`, append-only, cut to its newest 400 lines past 256 KB. Its reader is `hook_idle_timer.doctor_rows` (the doctor's "idle timer" row). Whether a session was already woken is read from its transcript (a user row carrying `[claudette idle-timer]`), never from this file.
- `logs/compact_done_decisions.jsonl` — every decision of `auto_done`'s PreCompact gate (the `compact_done` feature until 2026-10-15; the file kept its name), one JSON line each: `{ts, iso, session_id, trigger, decision: block|keep|pass, reason, idle_min, ctx_pct, sig}` (added 2026-10-14). Single writer: `hook_compact_done.py gate`, append-only, cut to its newest 400 lines past 256 KB. Its readers are in the same script: `wake` follows only the gate line whose `sig` (the transcript state the gate decided on) matches its own reading, so it wakes the compaction that was blocked and no other; `restore` re-injects the report only after a `keep` of the last 15 minutes. `idle_compaction.doctor_rows` quotes the newest `auto` line. Whether a session was already woken is read from its transcript (a user row carrying `[claudette compact-done]`), never from this file, as for the watchdog.
- `logs/idle_compaction_seen.json` — whether Claude Code compacts idle sessions on this machine: `{state: seen|unseen|off, last_seen, checked_at, setting_off}` (added 2026-10-14). Single writer: `idle_compaction.py`, through `refresh()` (called by `features_apply.py`, TTL 6 h; scans recent transcripts of 300 KB or more for Claude Code's `Compacted while idle` notice) and `note_seen()` (called by the compact_done gate on an idle `auto` compaction). `seen` holds for 30 days after the last sighting, and `prefs` reads an older `seen` as `unseen`. Read by `prefs.features()` for the `recommend_by` overlay (`CLAUDETTE_REGISTRY.md`) and by the doctor's `idle compaction` row. A cache of an observation: deleting it costs one scan.
- `logs/usage_chart_addr.json` — this machine's copy of the usage chart's artifact URL (added 2026-09-21): `{url, title, marker, cached_at}`. Single writer: `usage_chart.py addr --set`. **Machine-local on purpose and NOT a config file**: claudette has no synced per-user store and its repo must never carry one user's artifact address, so when this file is absent the address is discovered from the account (list your own artifacts, then `ArtifactData get meta/identity` on each candidate and take the one carrying the frozen `claudette:usage-chart:v1` marker — the title only narrows the candidates, it is not the key; the marker moved out of the artifact description on 2026-09-21 because no `Artifact` action returns one). Delete it and the next run rediscovers.
- `logs/usage_chart_cache.json` — the collector's read-through mtime plus the readings it has already parsed (added 2026-09-21). Single writer: `usage_chart.py collect`. Same role as any cache: delete it and the next run rebuilds from `claude_usage_snapshots/` (~100 s cold, 0.2 s warm). Keyed by `{fmt, pool, bucket, days}` — a different question starts over rather than mixing answers.
- `logs/usage_chart_pushed.json` — what this machine last published to the chart: `{flow: 2, ts, machine, windows{}, rows, reported{}, attempted_marks{}, pending, confirmed_at}`. Single writer: `usage_chart.py` — `prepare` records the attempt, `pushed --ok` promotes `attempted_marks` into `reported` (what the movement trigger compares against) and drops the database flow's keys (`live`, `attempted`, `retiring`, `strays`) from records written before 2026-09-22.
- `logs/usage_chart_mine.json` — this machine's published file as last built, `{v, m, tz, updated, docs[]}`. Single writer: `prepare`. The next file is built from it plus the fresh snapshots, which is what keeps a whole-file rewrite from shrinking history the snapshot folder no longer has. Missing = a new install: the recipe merges the chart's copy first. Read by `.chart` and `done_probe.probe_usage_chart()` to say how far behind the chart is WITHOUT walking the snapshot folder — the staleness signal is this timestamp against `claude_usage_last.json`'s mtime, which is one stat.
- `logs/chart_runner.json` — the chart runner's last outcome (added 2026-10-19): `{ts, state: running|ok|failed, rows, windows, model, id, session_state, reply, usage{input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens, model, responses}, reason, secs}`. Single writer: `chart_runner.py` (`launch` writes `running`, its `run` child the outcome). `launch` quotes a `failed` reason in the next done report's chart line; `chart_runner.py status` prints it.
- `logs/chart_runner_lock.json` — `{ts, pid}` while one update is under way on this machine; created with `O_EXCL` by `launch`, deleted by the `run` child or by `launch` when nothing is sent. Older than `LOCK_MAX` (`RUN_TIMEOUT + 300` s, longer than any live run) = a killed child, taken over.
- `logs/chart_runner_last.jsonl` — the transcript of the last background session, moved out of `~/.claude/projects` so it never lists as a session of its own. Overwritten each run; kept for diagnosis and for measuring what a run costs.
- `logs/usage_chart_work/` — ephemeral scratch for one `/claudette:chart` run (collected readings, the documents about to be written, a built page). No schema, no reader: every file in it is an input to the next command in the same run, and deleting the folder between runs is always safe. It lives under `logs/` because that is the gitignored, machine-local place; a run that can use the session's own scratchpad directory should prefer it.
- `logs/sess_index/<session_id>.json` — what THIS session's last `.sess` listing showed: `{ts, boot, map:{rank: session_id}}` (added 2026-09-15). Single writer: `dot_sess.py`, atomic replace, one file per session. It exists because a blocked dot-command's output reaches the transcript only as rendered text, so nothing records what was printed in a form that can be read back — and `.sess !r 7` must resolve `7` against **what the user read**, not a fresh scan: rows are ordered by transcript mtime, and the first resumed window renumbers everything below it. **Per session, not global**, so a listing in another console can never answer an index typed here (that collision is the wrong-launch the map exists to prevent). `boot` (from `sess_launch.boot_time()`) invalidates a map across a reboot, which matters because `--resume` keeps the session id: a session reopened after a reboot would otherwise find its own stale map. Self-pruning on write: maps from earlier boots are deleted, then the folder is capped at the newest 50. Holds ranks and ids only — no titles, no paths, no prompt text.
- `logs/proj_index/<session_id>.json` — the same record for the last `.proj` listing: `{ts, boot, map:{rank: project_slug}}` (added 2026-09-16). Same schema, same writers (`dot_sess.index_write/read`, given this directory), same boot-stamping and pruning as `sess_index` above, and same reason — `.proj !new 3` opens a session in project 3, which writes a transcript there and makes it project 1, so the index must resolve against what was printed. **A separate directory is the whole point**: one shared file and a `.proj` listing would silently answer a `.sess !r N`. Holds ranks and project-folder names only.
- `logs/launch/launch-<pid>-<ms>-<n>.{sh,ps1,cmd}` — the command of a session opened in a new Windows Terminal tab when that command holds a double quote (`.new "<title>"`; added 2026-11-16): wt drops inner quotes, so only this file's path crosses it (`sess_launch.py`, "WT ALSO DROPS INNER QUOTES"). Plain text, UTF-8, read once by the tab's shell when it starts. Single writer: `sess_launch.spawn`, which also deletes the files of this folder older than a day on each launch. No reader besides that tab.
- `logs/notes_typed.jsonl` — every `.note` / `..note` typed on this machine, one JSON line each: `{ts, session_id, transcript, cwd, channel: free|context, text}` (added 2026-09-28). Single writer: `dot_note.py`, append-only; two sessions noting in the same instant is the only collision and is accepted. **The transcript is the PRIMARY store and this file fills its gaps**: a reader of notes calls `dot_note.session_notes()`, which returns the transcript's notes plus the rows of this file the transcript does not hold, placed by time, because since client 2.1.295 a note typed mid-turn is recorded nowhere else (found 2026-10-14). A row never replaces a note the transcript holds. This file is also the ground truth `dot_note.verify()` holds transcripts against (a doctor row, so every update; and `dot_transcript_check.py`); a missing row typed mid-turn is expected there, and only one typed while the agent was idle, the shape the client still records, warns. Holds the note text verbatim, so it is as personal as the transcripts; gitignored like the rest of `logs/`, never pruned (notes are few and each one was typed by hand). **Where a note sits in a transcript is a frozen contract too**, since readers outside claudette depend on it, and `.note` itself writes none of it — the client does: (1) free channel — a `system` entry whose `content` opens `UserPromptSubmit operation blocked by hook` and whose FIRST `\n\nOriginal prompt: ` is followed by the prompt as typed (the hook's own text above it never carries the user's words, so that first marker is the client's); (2) typed while the agent works — through client 2.1.294, a `queue-operation` entry with `operation: remove`, `reason: dropped_by_hook`, whose `content` is the prompt (the hook runs when the prompt is queued and the client writes no system entry; never read the `enqueue` line, which a queued `..note` also has); from 2.1.295, no line at all, so this file is the only record. A plain prompt typed mid-turn is now written as `enqueue`, a `remove` with `reason: absorbed_mid_turn`, and an `attachment` of type `queued_command`; a mid-turn `..note` may land there too, which nothing reads yet (untested), and the merge above covers it meanwhile. Whether a row was typed mid-turn is read from the transcript's turns by time: a `system` entry of subtype `turn_duration` or `stop_hook_summary`, or an Esc's `[Request interrupted by user` entry, ends a turn; an `assistant` entry, a tool result or a typed prompt means the agent is at work (`dot_note.mid_turn_of()`); (3) `..` channel — the user's own prompt entry. Either prompt is a note when it is `.note`/`..note` (leading dots or `…`, name case-blind) followed by text that is not empty, `?` or digits only — the listing, usage and `.note N` land in the transcript too and are not notes (`dot_note.note_of()`). Compare whitespace-collapsed: the client's re-spacing must not read as a lost note. One entry from the day `.note` shipped also carries the text in the hook's part (an echo, since removed); reading the `Original prompt:` tail covers it.
- `logs/throttle_control.json` — throttle overrides (off/m, expiries). Single writer: the `/claudette:throttle` skill. Read by `hook_throttle.py`.
- `logs/throttle_notify.json` — last user-notification timestamp. Single writer: `hook_throttle.py`.
- `logs/throttle_registry.json` — map of `/claudette:throttle` job name → path of its `<job>_status.json` (job files live job-named in the relevant project folder). Single writer: the throttle skill.
- `logs/throttle_jobs/` — job files for PROJECT-LESS `/claudette:throttle` jobs only. Writer: the job's scheduled runs.
- `logs/throttle_calibration.json` — passive (own_tokens, d_used5) observations for a future usage estimator; no throttle decision reads it. Writers: throttle orchestrators (append-discipline, low frequency).
- `logs/git_upstreams/<slug>.json` — per-repo cache of upstream staleness (added 2026-07-27). One file per repo root (`<basename>-<md5[:8]>`), branch-keyed entries `{upstream, remote_hash, checked_at, error}` from a READ-ONLY TTL'd `ls-remote` (5 min; 2 min retry after errors — `git_upstreams.py:28-29` is the source of truth). Single writer: `git_upstreams.py` (module + CLI) — callers (hook_statusline.py badges `⚠↓N`/`⚠↓N+`/`⚠↓?` for the cwd repo and `(↓claudette)` for claudette's own; agents pre-edit via `bash "{S}/run.sh" git_upstreams.py <repo_root>`) never write the cache themselves. **Anti-goals:** never fetch/download objects, never write git config, never prompt (hardening — `GIT_TERMINAL_PROMPT=0`, ssh BatchMode, 3s timeouts — is per-invocation only). Kill switch: create `logs/git_upstreams/off`.
- `logs/config_runs/<YYYYMMDD-HHMMSS>_<pid>.log` — full transcript of one claudette run that **changed durable state** (added 2026-08-10): git traffic on the repos, config written to this machine, or both. Sections in the order they happened: `== pull ==` (written by `pull.sh`), `== apply ==` (`features_apply.py`), `== push ==` or any other section (`log_run.sh <section> -- <cmd>`). **One run = one file**: the entry point opens the log and hands the path down in `$CLAUDETTE_RUN_LOG`, so an apply triggered by a pull appends rather than starting its own — a chained `sync` is one file, a standalone `--feat` is one file with only an apply section. Append-discipline, one writer at a time. ANSI stripped; **newest 20 kept**, pruned on creation (deliberately bounded from day one, unlike `claude_usage_snapshots/`). No `_last` companion — nothing reads these on a hot path, so `--doctor` globs the newest (`paths.newest_run_log()`) and prints its path. **Read-only invocations write nothing**: `-s`, `--features-json`, `--doctor`, `--auth`, `status.sh`, `--preview-tone` (an audition loop would prune real applies out of the 20), `--update-plan`, `--features-table`, and `--explain` (a plan printed on every routine update would do the same). Why it exists: a caller that keeps only the tail of the output (`| tail -60`) destroys the pull section first, which is the part that explains why an apply changed anything — see `CLAUDETTE_DESIGN.md`. **Written masked** (since 1.2.5): every writer goes through `scripts/redact.py`, which replaces credential shapes (an `Authorization`/`extraHeader` value, a URL's `user:secret@`, the push guard's patterns, a `token=`/`password:`-style value) with `***`, and an apply masks older logs in place. A secret under a key name it does not recognize (a settings `env` value named otherwise) can still land here; `logs/` is gitignored and never pushed.
- `logs/last_apply.json` — the last apply's outcome `{ts, hooks_changed, argv, run_log}` (added 2026-08-12). Single writer: the `features_apply.py` apply path, every apply, atomic-enough overwrite. Exists because `--update-plan` (read-only) cannot recompute `hooks_changed` without re-running `assemble()`; its `restart_needed` therefore means "as of the last apply" — accurate in the `pull.sh` flow, where the plan prints right after the apply that wrote it.
- `logs/git_local_state.json` — per-repo `{ts, ahead, dirty}` booleans for the repos the status line's `repos` segment watches (added 2026-08-12). Same family as `git_upstreams/` and the deliberate complement to it: that cache answers "behind the remote?" from a read-only `ls-remote`, this one answers "holds local work?" from a real `git status` (~37 ms/repo), which is why it is TTL'd at 60s rather than run per render. Single writer: `hook_statusline.py`, atomic replace (several sessions render concurrently). Booleans only, never counts or filenames — the segment shows one arrow per repo, and `/claudette:done` is what enumerates dirt.
- `logs/audio_mixer_healed.json` — how often the sound hooks had to raise a silenced `python.exe` mixer slider (added 2026-09-28): `{ts, first_ts, count, devices, before}` — last heal, first heal, number of healing calls (not devices), devices changed by the last one, the last one's pre-heal `{volume, muted}`. Single writer: `winaudio.heal(record=)` (called by `hook_play_wav.py` and `hook_speak_notification.py`), atomic replace; several sessions can heal at once, so `count` is best-effort (a lost increment is accepted, a half-written file is not). A corrupt or non-object file restarts the count. Read by `--doctor`'s mixer row only. Delete it to reset the count. Why the hooks heal at all: `CLAUDETTE_DESIGN.md` "Hook audio silence".
- General rule for future logs here: keep each log type to a **distinct filename + single writer** (or append-discipline) so a shared `logs/` folder stays collision-free.
